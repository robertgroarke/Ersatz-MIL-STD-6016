## Scope

The standard specifies how Link 16 simulation data is represented and exchanged through DIS and HLA. It defines transport-facing data structures and fidelity levels; it does not publish the full operational semantics of MIL-STD-6016 or STANAG 5516 message payloads.

Link 16 messages are bit-encoded as required by the governing Link 16 message standard. Error-detection encoding need not be performed for simulation exchange. Where Reed-Solomon is indicated, the represented J word still consists of 70 data bits and 5 parity bits. Required exchange fields are populated even when a no-statement value is needed.

## Network header

The fixed 160-bit network header includes:

| Field | Width | Important values |
| --- | ---: | --- |
| Network Participation Group | 16 bits | 0-511 |
| Network number | 8 bits | 0-127 |
| TSEC CVLL | 8 bits | 0-127; 255 is no statement/wildcard |
| MSEC CVLL | 8 bits | 0-127; 255 is no statement/wildcard |
| Message type | 8 bits | 0 J-series; 1 RTT A/B; 2 RTT reply; 3 CVSD voice; 4 LPC-10; 5 LPC-12; 6 LET; 7 VMF |
| SISO version | 8 bits | 1 identifies the current format |
| Link 16 version | 8 bits | Version of the encoded Link 16 content |
| Time Slot ID | 32 bits | 17-bit time-slot number, padding, and 8-bit epoch |
| Perceived transmit time, integer | 32 bits | All ones means no statement |
| Perceived transmit time, fraction | 32 bits | All ones means no statement |

The time-slot number range is 0-98,303, with 131,071 as wildcard. Epoch values run 0-112, with 255 as wildcard. When Epoch is 112, the last valid Time Slot is 45,151.

## Fixed message-data header

The fixed message portion begins with a 48-bit header:

| Field | Width |
| --- | ---: |
| Time-slot type | 3 bits |
| Relay | 1 bit |
| Source track number | 15 bits |
| Secure data unit serial number | 16 bits |
| Padding | 13 bits |

A J word is stored in an 80-bit container: 75 native bits (70 data plus 5 parity) and 5 padding bits. Implementations must preserve the specified bit order; treating the storage container as a host integer is not a portable interchange rule.

## Version compatibility

Version 2.0 represents Link 16 message data as a bit stream. Version 1.0 used an array of 32-bit integers with byte-swapping rules. The versions are not wire-compatible without gateway handling. A receiver must use the declared SISO version rather than guessing from host byte order.

## Fidelity model

The standard defines increasing Time Slot Allocation fidelity levels from 0 through 4. Higher levels add progressively more detailed time-slot, network, and transmission behavior. A system must state the fidelity it implements; exchanging the same data structure does not prove equivalent radio or network behavior.

## TACSIT implementation boundary

- Parse only fields whose public layout is established by this standard or another cited public source.
- Keep unavailable J-series payload semantics opaque and retain raw bytes where policy permits.
- Validate sizes, versions, and no-statement values before exposing decoded fields.
- Do not infer unreported tracks, paths, engagements, weapons, intercepts, or fire-control solutions.
- Treat the HLA/DIS translations as informative where the standard marks them so.
